Custom Agents 템플릿

Codex custom agent는 반복되는 역할을 고정된 지침과 권한 범위로 분리하는 장치입니다. agent 이름을 먼저 늘리는 대신, 반복성, 권한, 산출물 형식, 검증 책임이 분명할 때만 템플릿으로 승격합니다.

이번 결론

Custom agent는 “자주 쓰는 작업자”가 아니라 “반복 가능한 책임 단위”입니다.

explorer, worker, reviewer, docs-maintainer처럼 역할이 자주 반복되고 출력 형식이 안정되어야 custom agent로 둘 가치가 있습니다. 한 번만 필요한 조사나 구현은 기본 subagent 또는 main Codex에게 맡기고, 템플릿은 실제로 반복되는 순간에만 늘립니다.

공식 기준 요약

  • 프로젝트 전용 agent는 .codex/agents/<name>.toml에 둡니다.
  • 개인 전역 agent는 ~/.codex/agents/<name>.toml에 둡니다.
  • 각 TOML 파일은 agent 하나를 정의합니다.
  • 필수 필드는 name, description, developer_instructions입니다.
  • model, model_reasoning_effort, sandbox_mode, mcp_servers, skills.config 같은 설정은 필요할 때만 명시합니다.
  • 파일명과 name을 맞추는 것이 가장 단순하지만, Codex가 agent를 식별하는 기준은 name입니다.
  • subagent는 명시적으로 요청했을 때만 생성되며, 병렬 agent는 토큰과 실행 시간이 더 듭니다.

무엇으로 분리할까

상황 선택 판단 기준
짧은 수정, 맥락 공유가 중요함 Main Codex 추가 agent를 띄우는 비용보다 현재 대화 맥락이 더 중요합니다.
코드베이스의 서로 다른 영역을 조사함 Explorer subagent 읽기 중심 질문을 병렬로 나눌 때 효과가 큽니다.
서로 겹치지 않는 파일 범위를 구현함 Worker subagent 소유 파일과 검증 명령을 명시할 수 있을 때만 적합합니다.
반복되는 역할과 출력 형식이 있음 Custom agent 매번 같은 지침을 복사하고 있다면 템플릿으로 승격합니다.
작업 절차나 참고 자료를 재사용함 Skill 역할보다 절차, 체크리스트, 스크립트가 핵심이면 skill이 맞습니다.
도구 실행 전후를 자동 검증함 Hook 사람이 잊기 쉬운 기계적 검사에만 제한적으로 씁니다.

기본 작성 규칙

  1. description에는 “언제 써야 하는지”와 “언제 쓰면 안 되는지”를 함께 적습니다.
  2. developer_instructions에는 역할, 금지 행동, 산출물 형식, 검증 기준을 넣습니다.
  3. 읽기 전용 agent는 sandbox_mode = "read-only"를 우선 검토합니다.
  4. 모델명은 자주 바뀔 수 있으므로 특별한 이유가 없으면 부모 세션 기본값을 상속합니다.
  5. project agent는 repo의 작업 규칙과 같이 버전 관리하고, 개인 agent는 공개 저장소에 넣지 않습니다.
  6. 권한이 큰 agent일수록 출력 계약을 짧고 엄격하게 둡니다.

Explorer 템플릿

읽기 전용 조사 agent입니다. 구현 제안보다 실제 근거와 파일 위치를 모으는 역할에 집중합니다.

name = "project_explorer"
description = "Read-only codebase explorer for answering narrow architecture and behavior questions."
sandbox_mode = "read-only"

developer_instructions = """
Stay in exploration mode.
Answer the assigned question with concrete file and symbol references.
Prefer rg, targeted file reads, and existing tests over broad scans.
Do not edit files.
Do not propose a large redesign unless the parent agent explicitly asks.
Return: findings, evidence, uncertainty, and suggested next inspection.
"""

Worker 템플릿

분리된 파일 범위를 맡아 구현하는 agent입니다. 다른 사람이나 다른 agent의 변경을 되돌리지 않는다는 규칙을 항상 포함합니다.

name = "scoped_worker"
description = "Implementation worker for a clearly bounded, non-overlapping file scope."

developer_instructions = """
You are not alone in the codebase.
Own only the files or modules explicitly assigned by the parent agent.
Do not revert user changes or changes made by other agents.
Follow existing project patterns and keep edits narrow.
Run the narrowest relevant validation for your changed surface.
Return: changed files, behavior change, validation result, and remaining risk.
"""

Reviewer 템플릿

구현과 분리된 검토 agent입니다. 스타일 취향보다 버그, 보안, 회귀, 테스트 누락을 먼저 봅니다.

name = "risk_reviewer"
description = "Code reviewer focused on correctness, security, regressions, and missing tests."
sandbox_mode = "read-only"

developer_instructions = """
Review like an owner.
Lead with findings ordered by severity.
Ground every finding in file and line references when possible.
Prioritize correctness, security, behavior regressions, data loss, and missing tests.
Avoid style-only comments unless they hide a real risk.
Do not edit files.
Return: findings, open questions, test gaps, and residual risk.
"""

Docs Maintainer 템플릿

학습 사이트나 playbook을 갱신할 때 쓰는 문서 agent입니다. 공식 문서 확인과 공개/비공개 분리를 책임으로 둡니다.

name = "docs_maintainer"
description = "Documentation maintainer for learning notes, official-source checks, and public/private separation."
sandbox_mode = "workspace-write"

developer_instructions = """
Update documentation from verified sources.
For OpenAI product behavior, use official OpenAI docs first.
Keep private playbook notes separate from public learning pages.
Do not publish secrets, local-only paths, tokens, or personal credentials.
Prefer HTML pages for public reading surfaces in MyCoding Book.
Return: pages changed, source links checked, validation result, and next queue item.
"""

프롬프트에 같이 줘야 할 것

항목 예시
작업 범위 src/auth/*만 조사, 또는 codex/*.html만 수정
권한 읽기 전용, 특정 파일만 수정, 테스트 실행만 허용
산출물 발견 사항 5개 이하, 변경 파일 목록, 검증 결과, 남은 위험
통합 기준 main agent가 결과를 병합하고 최종 판단을 유지
중단 기준 권한 상승, 파괴적 명령, 범위 밖 파일 변경 필요 시 멈춤

MyCoding Book 적용 기준

  • Agent 설계와 운영 기준은 언제 agent를 나눌지 판단합니다.
  • 이 문서는 반복되는 역할을 custom agent 템플릿으로 고정합니다.
  • Skills 문서는 절차와 참고 자료를 재사용하는 방식을 다룹니다.
  • Hooks 문서는 생명주기 자동 검증과 guardrail을 다룹니다.
  • 다음 단계의 agentic-rag.html에서는 agent가 기억, 검색, vector store를 언제 붙여야 하는지 정리합니다.

업데이트 루틴

  1. 월 1회 OpenAI Codex subagents, skills, hooks 문서를 확인합니다.
  2. 새 필드나 동작이 생기면 템플릿에 바로 넣지 말고 “검토 후보”로 둡니다.
  3. 실제 작업에서 세 번 이상 반복된 역할만 custom agent로 승격합니다.
  4. 모델명, 권한, MCP 서버 설정은 공개 문서보다 개인 playbook에서 먼저 시험합니다.
  5. 검증된 내용만 공개 HTML에 반영하고, 실험 실패 기록은 reference나 legacy로 분리합니다.

공식 확인 출처

  • OpenAI Codex Subagents - custom agent 위치, 필수 필드, optional config 기준
  • OpenAI Codex Skills - skill의 재사용 단위와 progressive disclosure 기준
  • OpenAI Codex Hooks - hook 설정, trust, lifecycle event 기준
