Codex 업데이트 루틴

AI coding 도구는 빠르게 바뀌지만, 모든 변화를 즉시 따라갈 필요는 없습니다. 이 문서는 공식 출처를 주기적으로 확인하고, 개인 playbook과 공개 MyCoding Book에 무엇을 반영할지 결정하는 루틴입니다.

이번 결론

월 1회 정기 점검, 필요할 때 긴급 점검, 공개 전 검증을 기본값으로 둡니다.

모델명, 기능명, hook event, skill 구조, MCP 연결 방식은 계속 바뀔 수 있습니다. 그래서 core 문서는 원칙 중심으로 유지하고, 특정 날짜의 변화는 updates 문서에 기록합니다.

점검 주기

주기 확인 대상 결과물
필요 시 현재 작업을 막는 기능 변화, 오류, 권한 문제 작업 메모 또는 작은 수정
월 1회 Codex changelog, feature maturity, models, subagents, skills, hooks, MCP updates 문서와 필요한 core 문서 수정
분기 1회 legacy 문서, practice 문서, 공개/비공개 경계 content audit와 legacy map 갱신
큰 기능 도입 전 RAG, browser/computer use, automation, connector, plugin 작은 실험, 검증 결과, 도입 판단

공식 출처 체크리스트

  1. Codex changelog: 앱, CLI, IDE, web, automation, browser 기능 변화를 확인합니다.
  2. Feature maturity: stable, beta, experimental 같은 성숙도 라벨을 확인해 공개 문서 표현 강도를 조절합니다.
  3. Models: 현재 권장 모델과 Codex용 모델 변화를 확인하되 core 문서에는 날짜 없는 단정 표현을 피합니다.
  4. Subagents: 병렬 agent, custom agent, sandbox inheritance, optional config 필드 변화를 확인합니다.
  5. Skills: 저장 위치, progressive disclosure, trigger 방식, plugin 배포 기준을 확인합니다.
  6. Hooks: event, matcher, trust review, supported handler, Windows command override 변화를 확인합니다.
  7. MCP/Connectors: transport, OAuth, tool search, connector 권한 모델 변화를 확인합니다.
  8. Retrieval/Evals: file search, vector store, eval 기준이 agentic RAG 문서와 충돌하지 않는지 봅니다.

반영 등급

등급 의미 처리
Note 흥미롭지만 현재 작업 방식에 영향이 작음 playbook이나 updates 후보에만 기록
Watch 곧 중요해질 수 있지만 아직 안정성이나 사용성이 불확실함 Feature maturity와 다음 달 changelog에서 재확인
Adopt 현재 workflow에 바로 도움이 되고 검증 가능함 core HTML 문서에 반영하고 작은 실험 결과를 기록
Rewrite 기존 문서 설명이 공식 동작과 충돌함 해당 문서 수정, content audit 갱신, 배포 확인
Legacy 현재 기준과 다르지만 기록 가치가 있음 legacy map에 남기고 core 문서에서 직접 의존하지 않음

공개 전 검증

  • 공식 출처 URL과 확인 날짜를 남깁니다.
  • 모델명과 기능명은 현재 시점 기준임을 분명히 합니다.
  • private playbook 경로, 계정 정보, 토큰, 고객/프로젝트 세부사항은 공개 HTML에 넣지 않습니다.
  • OpenAI와 Anthropic 문서가 서로 다르면 제품별로 분리하고 한쪽 용어를 다른 쪽에 덮어쓰지 않습니다.
  • 기능이 experimental 또는 beta라면 “운영 기본값”처럼 쓰지 않습니다.
  • 링크, JS 문법, 배포 URL을 확인한 뒤 완료로 표시합니다.

이 사이트의 적용 흐름

  1. 공식 출처를 확인하고 변경 후보를 적습니다.
  2. 개인 실험이나 민감한 메모는 private playbook에 먼저 둡니다.
  3. 공개 가능한 핵심 판단만 MyCoding Book HTML로 승격합니다.
  4. content audit와 legacy map을 갱신합니다.
  5. GitHub push 뒤 Vercel 배포와 공개 URL을 확인합니다.

다음 작업 후보
