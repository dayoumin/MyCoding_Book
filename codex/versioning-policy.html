Claude Legacy와 모델 업데이트 정책

Claude Code와 OpenAI 모델은 계속 바뀝니다. 이 사이트는 특정 시점의 기능명이나 모델명을 절대 기준으로 삼지 않고, 공식 문서 확인일과 적용 범위를 함께 기록합니다.

Claude Code 문서 처리 방식

분류처리예시
Codex에도 그대로 유효 표현만 Codex 기준으로 재작성 MCP 권한 분리, subagent 역할 분리, 검증 루프
Claude Code 전용 legacy에 보관하고 Codex 문서에서 직접 의존하지 않음 Claude 설정 파일 경로, Claude 전용 hook 입력 필드
Codex에서 직접 지원 OpenAI Codex 문서를 기준으로 새 문서 작성 Codex subagents, skills, hooks, MCP
낡았거나 검증 불가 공개 사이트에서 내리고 playbook 원본에만 보관 공식 문서와 충돌하는 오래된 예시

Claude 자료를 바로 전면 재작성하지 않는 이유

Claude Code도 subagents, hooks, MCP가 계속 바뀌고 있습니다. 공식 Anthropic 문서 기준으로 보면 subagents는 별도 context와 tool permissions를 갖고, hooks는 command hook, JSON output, MCP tool matcher, 보안 주의사항까지 포함합니다. 또한 Codex도 subagents, skills, hooks 문서가 별도로 생겼으므로 오래된 문서를 단순히 용어만 바꿔 옮기면 위험합니다.

원칙

Claude 문서는 재작성보다 먼저 감사를 합니다. 유효성 확인 없이 새 사이트의 core 문서로 승격하지 않습니다.

모델명 업데이트 정책

GPT-5.5처럼 현재 기준 모델명은 계속 바뀝니다. 그래서 core 문서에는 특정 모델명을 박아두지 않고, "현재 공식 모델 문서 기준"이라는 표현을 사용합니다. 특정 모델명은 날짜가 있는 업데이트 문서에만 기록합니다.

  • Core 문서: 현재 권장 모델, Codex 전용 coding model처럼 역할 중심으로 작성
  • Update 문서: 2026-05-26 기준 GPT-5.5 확인처럼 날짜와 함께 작성
  • Reference 문서: 공식 모델 문서 링크를 유지
  • 실제 프로젝트: 모델명 변경은 코드 변경과 prompt 검증을 함께 수행

월간 유지보수 체크

  1. OpenAI 모델 문서에서 current coding / agentic model 기준 확인
  2. Codex use cases와 release notes에서 workflow 변화 확인
  3. Anthropic Claude Code 문서에서 skills, hooks, subagents, MCP 변화 확인
  4. 바뀐 내용이 내 작업 방식에 영향을 주는지 playbook에 기록
  5. 공개 가능한 내용만 MyCoding Book HTML 문서로 승격

공식 확인 소스

  • OpenAI model docs - 현재 모델과 기능 지원 범위 확인
  • OpenAI Codex use cases - Codex workflow 확인
  • OpenAI Codex subagents - Codex subagent workflow 확인
  • OpenAI Codex skills - Codex skill 구조 확인
  • OpenAI Codex hooks - Codex hook 지원 범위 확인
  • Anthropic Claude Code subagents - Claude subagent 구조 확인
  • Anthropic Claude Code hooks - Claude hook 현재 구조 확인
  • Anthropic Claude Code MCP - Claude MCP 연계 확인
