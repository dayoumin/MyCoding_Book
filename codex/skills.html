Codex Skills와 재사용 루틴

Skill은 반복되는 작업 절차와 참고 자료를 Codex가 필요할 때 꺼내 쓰게 하는 구조입니다. 모든 지식을 skill로 만들기보다, 자주 반복되고 입력/출력/검증 기준이 안정된 일만 skill로 승격합니다.

이번 결론

Skill은 “역할”보다 “절차”에 가깝습니다.

explorer, worker, reviewer처럼 책임을 나누는 것은 custom agent에 가깝고, 문서 갱신, 배포 검증, spreadsheet 처리처럼 반복 절차와 산출물 형식이 분명한 일은 skill에 가깝습니다.

공식 구조 요약

  • Skill은 폴더와 SKILL.md 파일로 구성합니다.
  • SKILL.md frontmatter에는 최소 name과 description을 둡니다.
  • Codex는 skill을 명시적으로 호출하거나, 작업이 description과 맞을 때 암시적으로 선택할 수 있습니다.
  • CLI/IDE에서는 /skills 또는 $ mention으로 skill을 직접 부를 수 있습니다.
  • description은 trigger 단어, 적용 범위, 쓰면 안 되는 경우를 짧고 앞쪽에 적어야 합니다.
  • Codex는 skill 변경을 자동 감지하지만, 보이지 않으면 재시작합니다.

최소 SKILL.md

처음에는 instruction-only skill로 시작합니다. 스크립트는 꼭 deterministic behavior가 필요할 때만 붙입니다.

---
name: docs-publisher
description: Use when updating public MyCoding Book HTML pages from verified official sources. Do not use for private playbook-only notes.
---

Follow this workflow:

1. Check official sources first.
2. Separate private playbook notes from public HTML.
3. Update the smallest relevant page.
4. Validate links, JavaScript syntax, and deployment.
5. Return changed pages, source links, validation result, and next queue item.

저장 위치

범위 위치 추천 용도
Repo current directory $CWD/.agents/skills 특정 작업 폴더나 microservice에만 필요한 skill
Repo parent folders $CWD/../.agents/skills 중첩 repo나 여러 하위 폴더가 공유하는 skill
Repo root $REPO_ROOT/.agents/skills 팀이나 프로젝트 전체가 공유할 skill
User $HOME/.agents/skills 개인이 여러 repo에서 쓰는 skill
Admin /etc/codex/skills 공유 환경, container, SDK 자동화에서 기본 제공할 skill
System Codex에 bundled skill-creator, skill-installer처럼 모두에게 제공되는 skill

언제 skill로 만들까

상황 선택 이유
매번 같은 절차와 산출물 형식이 반복됨 Skill 절차를 재사용할 수 있고 결과 형식도 안정됩니다.
역할, 책임, 파일 소유권을 나눠야 함 Custom agent 작업자 분리와 병렬 실행이 핵심입니다.
도구 실행 전후를 자동 검사해야 함 Hook 사용자가 잊기 쉬운 기계적 guardrail에 맞습니다.
외부 도구나 계정 데이터가 필요함 MCP / Connector skill은 절차이고, 외부 접근은 별도 권한 모델이 필요합니다.
한 번만 하는 판단이나 설계 결정 문서 또는 체크리스트 skill로 만들면 관리 대상만 늘어납니다.

Description 작성법

암시 호출은 description에 크게 의존합니다. 짧지만 경계가 분명해야 합니다.

좋은 요소 예시
Trigger 단어 “Use when creating or updating public HTML learning pages...”
적용 범위 “for MyCoding Book documentation updates”
금지 범위 “Do not use for private playbook-only notes.”
산출물 힌트 “Return changed pages, source links, validation result...”

Instruction 설계

  1. 먼저 입력과 출력 형식을 정합니다.
  2. 공식 출처, local file, browser evidence처럼 근거 우선순위를 둡니다.
  3. 권한이 필요한 도구는 skill 안에서 자동 승인하지 않고 사용자/상위 agent 판단으로 남깁니다.
  4. 스크립트가 있으면 언제 실행하고 실패하면 어떻게 보고할지 적습니다.
  5. 완료 보고 형식을 고정해 다음 작업자가 바로 이어받게 합니다.

Scripts와 assets

Skill 폴더에는 필요하면 scripts, references, assets를 둘 수 있습니다. 하지만 기본값은 instruction-only입니다. 스크립트는 format 변환, 검증, 반복 계산처럼 사람이 매번 손으로 하면 실수하기 쉬운 작업에만 둡니다.

  • scripts: deterministic validation, conversion, rendering, export
  • references: skill이 자주 참조하는 긴 문서나 예시
  • assets: 템플릿, 이미지, style guide, fixture
  • 주의: token, secret, 개인 경로, 고객 데이터는 skill asset에 넣지 않습니다.

Plugin으로 배포할 때

직접 skill 폴더는 local authoring과 repo-scoped workflow에 좋습니다. 여러 skill을 묶거나 app integration, MCP server configuration, presentation assets와 함께 배포하려면 plugin으로 패키징합니다.

방식 적합한 경우 주의
Local skill folder 개인 실험, repo 전용 절차 배포보다는 작성과 검증에 초점
Curated install 공식/큐레이션 skill을 개인 환경에 설치 $skill-installer로 설치하고 필요하면 재시작
Plugin 여러 skill, MCP, app mapping을 묶어 재사용 권한, dependency, UI metadata까지 함께 검토

선택 메타데이터

필요하면 agents/openai.yaml에 UI metadata, implicit invocation 정책, tool dependency를 추가할 수 있습니다. 기본 skill에는 필요 없고, 앱에서 노출되거나 특정 MCP 의존성이 있을 때만 검토합니다. 

interface:
  display_name: "Docs Publisher"
  short_description: "Update public learning docs from verified sources"
  default_prompt: "Update the relevant MyCoding Book page and validate links."

policy:
  allow_implicit_invocation: false

dependencies:
  tools:
    - type: "mcp"
      value: "openaiDeveloperDocs"
      description: "OpenAI Docs MCP server"
      transport: "streamable_http"
      url: "https://developers.openai.com/mcp"

Enable / Disable

skill을 삭제하지 않고 비활성화하려면 ~/.codex/config.toml의 [[skills.config]]를 사용합니다.

[[skills.config]]
path = "/path/to/skill/SKILL.md"
enabled = false

설정 변경 후에는 Codex를 재시작합니다.

운영 원칙

  1. skill은 하나의 일만 맡깁니다.
  2. description은 짧고 trigger가 분명해야 합니다.
  3. 처음에는 instruction-only로 만들고, 스크립트는 검증된 반복 작업에만 추가합니다.
  4. 공개 skill에는 private path, token, 고객 데이터, 개인 실험 로그를 넣지 않습니다.
  5. 암시 호출이 위험하면 allow_implicit_invocation: false를 검토합니다.
  6. 팀이나 여러 repo에 배포할 skill은 plugin으로 승격할지 따로 판단합니다.
