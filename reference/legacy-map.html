Legacy 원본 매핑

오래된 Claude Code 원본 MD와 공개 HTML 문서가 어디로 흡수됐는지 추적합니다. 이 표는 삭제 목록이 아니라, 새 Codex 기준으로 재작성할 때 무엇을 참고하고 무엇을 분리할지 정하는 지도입니다.

매핑 원칙

원본은 보존하고, 공개 학습면은 Codex 기준으로 읽습니다.

Claude 전용 설정 경로, 명령, hook 입력 형식은 legacy로 남깁니다. 반대로 agent 분리, 검증 루프, MCP 권한 모델처럼 Codex에도 필요한 개념은 새 HTML 문서에 흡수합니다.

  • Absorbed: 핵심 판단이 새 Codex 문서에 이미 반영됨
  • Legacy only: Claude Code 자료로만 보관하고 새 문서에서 직접 의존하지 않음
  • Rewrite next: 공식 문서 확인 뒤 새 Codex 문서로 재작성할 후보
  • Practice later: 학습 예제로 남기되 지금의 Codex core에는 넣지 않음

다음 작업 순서

  1. Browser 검증: MCP 문서의 Playwright / Chrome DevTools 후보를 browser workflow 문서와 연결합니다.
  2. Skill 생성 검토: docs-publisher나 legacy-auditor skill을 실제 repo 또는 개인 skill로 둘지 판단합니다.
  3. Practice 정리: product, video, monorepo 실습은 core 문서와 분리하고 나중에 최신 workflow로 갱신합니다.
  4. 운영 연결: Project Operations 앱에서 GitHub, Vercel, Sentry connector 후보를 별도 검토합니다.
