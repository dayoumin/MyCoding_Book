Codex Hooks 운영 기준

Hooks는 Codex의 agentic loop 중간에 결정적인 스크립트를 끼워 넣는 장치입니다. 모든 검증을 hook으로 옮기기보다, 반복적이고 기계적으로 판정할 수 있는 정책에만 씁니다.

이번 결론

Hook은 마지막 안전망이지, 작업 설계의 대체물이 아닙니다.

AGENTS.md, 좁은 테스트, 리뷰 루프가 먼저입니다. Hook은 위험 명령 차단, 필수 검증 누락 방지, 세션 시작 컨텍스트 주입처럼 자동화할 가치가 확실할 때만 둡니다.

언제 hook을 쓰나

상황 추천 이유
삭제, 배포, 권한 변경처럼 위험한 명령 PreToolUse 또는 PermissionRequest 실행 전에 차단하거나 승인 판단을 보강해야 합니다.
작업 종료 전에 반드시 확인할 품질 기준 Stop 테스트 누락, diff review 누락, 문서 업데이트 누락을 마지막에 잡습니다.
도구 실행 결과를 로그나 메모리로 남겨야 함 PostToolUse 이미 실행된 결과를 분석하거나 기록하는 데 맞습니다.
새 세션마다 같은 컨텍스트를 주입해야 함 SessionStart 프로젝트 운영 메모나 최근 결정 사항을 자동으로 올릴 수 있습니다.
subagent 결과가 특정 형식을 지켜야 함 SubagentStop 병렬 agent 결과를 통합하기 전에 형식과 누락을 점검합니다.
한 번만 하는 판단, 제품 방향 결정 Hook 비추천 체크리스트나 문서 기준이 더 투명합니다.
복잡한 리팩터링 전체 품질 판정 Hook 단독 비추천 테스트, 리뷰 agent, 수동 diff review를 함께 써야 합니다.

현재 Codex 기준 핵심

  • Hooks는 기본적으로 켜져 있으며, 필요하면 config.toml에서 [features].hooks = false로 끌 수 있습니다.
  • Codex는 hooks.json 또는 config.toml 안의 [hooks] 설정을 읽습니다.
  • 대표 위치는 ~/.codex/hooks.json, ~/.codex/config.toml, <repo>/.codex/hooks.json, <repo>/.codex/config.toml입니다.
  • 여러 위치에서 같은 이벤트에 매칭되는 hook이 있으면 모두 실행됩니다.
  • 여러 command hook은 동시에 시작될 수 있으므로 한 hook이 다른 hook의 시작을 막는 구조로 설계하면 안 됩니다.
  • 현재 실제로 실행되는 handler는 type: "command"입니다. prompt와 agent handler는 파싱되지만 실행되지 않습니다.
  • async: true command hook도 아직 실행되지 않습니다.
  • 프로젝트 로컬 hook은 프로젝트 .codex/ layer가 trusted일 때만 로드됩니다.

주요 이벤트

이벤트 쓰임 주의
SessionStart 세션 시작, resume, clear, compact 시 컨텍스트 주입 너무 많은 내용을 넣으면 오히려 작업 집중도가 떨어집니다.
UserPromptSubmit 사용자 입력 전처리, 민감정보 검사 개인용 사이트에서는 과도한 자동 차단보다 경고 중심이 낫습니다.
PreToolUse Bash, apply_patch, MCP tool 호출 전 검사 완전한 enforcement boundary는 아닙니다. 다른 도구 경로로 우회 가능한 경우가 있습니다.
PermissionRequest 승인이 필요한 작업의 allow/deny 판단 보강 승인 흐름을 대체하기보다 위험 신호를 더 잘 드러내는 용도로 씁니다.
PostToolUse 도구 실행 후 결과 검토, 로그, 추가 컨텍스트 이미 실행된 부작용을 되돌릴 수 없습니다.
SubagentStart subagent 시작 시 역할별 추가 컨텍스트 주입 시작 자체를 막는 이벤트로 보지 않습니다.
SubagentStop subagent 결과 형식과 누락 점검 병렬 결과를 합치기 전 요약 품질을 확인하는 데 좋습니다.
Stop 응답 종료 직전 최종 품질 게이트 무한 반복을 막기 위해 이미 continuation된 상태를 반드시 고려합니다.

최소 설정 예시

프로젝트 로컬 hook은 repo root 기준 경로를 안정적으로 계산하는 편이 좋습니다.

{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "^Bash$",
        "hooks": [
          {
            "type": "command",
            "command": "node \"$(git rev-parse --show-toplevel)/.codex/hooks/check-bash.mjs\"",
            "timeout": 30,
            "statusMessage": "Checking Bash command"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "node \"$(git rev-parse --show-toplevel)/.codex/hooks/final-check.mjs\"",
            "timeout": 30,
            "statusMessage": "Checking final response"
          }
        ]
      }
    ]
  }
}

운영 원칙

  1. 먼저 AGENTS.md에 정책을 쓴다.
  2. 반복해서 어기는 기계적 규칙만 hook 후보로 올린다.
  3. hook은 작게 유지하고, 복잡한 판단은 테스트나 reviewer agent로 뺀다.
  4. non-managed command hook은 trust review가 필요하다는 점을 전제로 운영한다.
  5. 팀/개인 환경에서 absolute path, Windows override, timeout을 명시한다.
  6. 실패 메시지는 Codex가 다음 행동을 알 수 있게 구체적으로 쓴다.
  7. 민감정보를 외부 HTTP로 보내는 hook은 개인용 playbook에 먼저 남기고 공개 사이트에는 절대 토큰을 쓰지 않는다.
