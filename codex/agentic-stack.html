Agentic Coding Stack 변화

Agentic coding은 "AI가 코드를 써준다"에서 끝나지 않습니다. 데이터, 검색, 도구 연결, 검증, 배포 관찰까지 개발 스택의 기본 구성이 바뀌고 있습니다.

새로운 기본 구성

영역왜 중요해졌나학습 포인트
Vector store / RAG 코드, 문서, 이슈, 운영 기록을 agent가 검색 가능한 지식으로 써야 함 임베딩, chunking, citation, freshness, 권한 분리
Multi-agent workflow 작성, 리뷰, 검증, 조사 역할을 나눠야 긴 작업의 품질이 올라감 역할 분리, handoff, 충돌 방지, 최종 통합 책임
MCP / Connectors agent가 GitHub, DB, 문서, 브라우저를 직접 다룰 수 있음 읽기/쓰기 권한, 승인 흐름, audit trail
Evals / verification agent가 만든 결과를 사람 감으로만 판단하기 어려움 테스트, lint, browser evidence, regression checks
Context engineering 모델 성능보다 어떤 맥락을 주는지가 결과를 크게 좌우함 AGENTS.md, skill, memory, docs, examples

DB와 vector store 관점

앞으로 프로젝트 DB는 트랜잭션 데이터만 담는 장소가 아닙니다. 문서 검색, 코드 검색, 사용자 피드백, 운영 이벤트를 agent가 이해할 수 있게 연결하는 층이 필요합니다. 그래서 일반 DB, vector store, search index, object storage의 역할 구분을 프로젝트 초기에 정해야 합니다.

학습 목표

vector store를 "AI 기능 하나"로 보지 말고, 프로젝트 지식과 agent 작업 품질을 유지하는 운영 인프라로 봅니다.

세부 판단 기준은 Agentic RAG 운영 기준에서 이어서 정리합니다.

멀티 agent 관점

멀티 agent는 agent 수를 늘리는 것이 아니라 역할과 책임을 분리하는 것입니다. 조사 agent, 구현 agent, 리뷰 agent, 검증 agent를 나눌 수 있지만 최종 통합 책임은 하나의 흐름에 있어야 합니다.

  • 병렬 조사는 가능하지만 같은 파일을 동시에 고치게 두면 위험하다.
  • 검증 agent는 구현 agent와 다른 관점을 가져야 한다.
  • handoff에는 요약보다 증거와 변경 파일이 포함되어야 한다.

공식 출처로 계속 확인할 것

  • OpenAI model docs - coding, computer use, subagent에 적합한 모델 변화 확인
  • OpenAI release notes - 앱 기능과 Codex workflow 변화 확인
