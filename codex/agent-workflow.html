Agent AI Coding 작업 흐름

Agent에게 일을 맡긴다는 것은 더 크게 말하는 것이 아니라, 목표와 검증 기준을 더 선명하게 주는 일입니다.

세부 설계 문서

agent를 실제로 나누기 전에는 Agent 설계와 운영 기준을 먼저 봅니다.

이 문서가 작업 흐름의 큰 그림이라면, agent 설계 문서는 subagent, skill, hook, MCP, RAG를 어떤 기준으로 분리할지 다룹니다.

작업을 나누는 기준

상황추천 방식검증
작고 명확한 수정현재 대화에서 바로 처리좁은 test, typecheck, diff review
여러 파일을 읽어야 하는 조사먼저 구조 파악 후 필요한 부분만 수정근거 파일과 변경 파일 확인
긴 목표와 반복 작업goal 기반 작업 또는 단계별 체크리스트중간 산출물, 최종 smoke check
서로 독립적인 탐색병렬 agent 또는 분리된 조사 흐름결과 병합 전 충돌 확인

좋은 요청의 형태

  • 결과물이 무엇인지 먼저 말한다.
  • 변경해도 되는 범위와 건드리면 안 되는 범위를 나눈다.
  • 검증 기준을 함께 준다.
  • 불확실한 제품 판단은 보수적으로 맡긴다.

나의 기본 루프

  1. 현재 코드와 문서를 읽는다.
  2. 작업 범위를 한 번 좁힌다.
  3. 필요한 변경을 한다.
  4. 가장 좁은 검증을 실행한다.
  5. diff를 보고 사용자 관점으로 설명한다.
